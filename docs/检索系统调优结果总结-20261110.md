# 检索系统调优结果总结

- 整理日期：2026-11-10
- 系统形态：全离线 CPU 架构，Ollama qwen2.5:7b 对话，bge-m3 向量，bge-reranker-base 进程内精排，Chroma 本地持久化
- 数据纪律：本文所有指标均取自仓库内实测报告或代码常量，逐条附来源路径。预估数字与实测数字分表标注，禁止混读。
- 配套清单：2026 年 11 月两波 P0 修复尚未做金标真机回归，其效果证据停留在离线单测与架构正确性层面，本文单独成节，不并入真机指标。

## 1. 结论摘要

检索层在生产金标上首次实测即接近天花板，文档命中率 98.0%，第二次起稳定在 100%，PDF 页码准确率全程 100%。调优的主要收益实际发生在答案合成与链路收口层，端到端通过率从首跑 17/50（34.0%）提升到 40/50（80.0%）。

早期 35 题离线实验集上，查询改写叠加文档权重把 Hit@1 从 36.4% 拉到 75.8%，这是仓库内唯一一组同数据集、同脚本、带前后对照的召回率对照实验。

代价同样明确。端到端 P50 延迟长期处于 140 至 180 秒量级，M3 覆盖扫描上线后 P50 升至 181.8 秒，属于用 CPU 时间换答案完整性。检索 MRR 三次实测在 0.9269 至 0.9473 间波动，不存在单调改善叙事。

## 6. 负面实验、回退与结构性权衡

记录失败与波动的价值高于只记录成功，这些条目直接决定了后续调优的禁区。

1. 故障边界切块负面实验。按故障编号重新切块使块数 301 降到 283，fault Hit@1 从 28.6% 反降到 14.3%，MRR 降 0.095，根因是长块词频稀释。方案弃用，留档在 RAG_QUALITY_REPORT 第 9.4 节。
2. BM25 warmup 上线初期的分词回退。langchain 默认预处理器把中文切成单字，金标实测 MRR 从 0.9388 反降到 0.9354，jieba 分词修复后恢复。证据在 retriever.py 第 43 至 48 行注释。
3. RRF 权重误用事故。权重曾直接乘进 RRF 分，1.5 倍权重等价于前移约 20 个 rank 位，导致 F02 查询正确资料在截断前出局。修正为裸分主键、权重仅裁决同分，证据在 retriever.py 第 920 至 923 行。
4. few-shot prompt 污染。含具体型号的范例被 7B 模型照抄，虚构禁忌材料污染真实答案，方案回退并加防复活单测。
5. 章戳细切的双向权衡。细切让精确定位题受益，综合题却因知识块更小更纯而更容易漏结论，12 题探针仅 3 题通过。这是切块粒度与小模型注意力的结构性矛盾，靠 M3 编排补偿而非继续改切块。
6. 延迟成本。M3 后 P50 从 157.2 秒升到 181.8 秒，P95 达 360.7 秒。CPU 上 3.6 tok/s 的生成速度是硬约束，任何增加输出 token 的编排都要用真机延迟回归确认代价可接受。
7. 剩余 10 题 fail 的归因。缺失资料全部在注入上下文内，属 7B CPU 注意力天花板与生成自截断，继续磨 prompt 边际收益已尽，进一步突破需要更大模型或综合题专用编排。
