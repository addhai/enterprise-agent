# 会话日志（第 3 层）

> **只追加，不覆盖。** 每次开发会话结束后，在文件末尾加一节。
> 这一层不参与日常上下文（不喂给 AI），只在「想不起来某次为什么这么改」时翻查。
>
> 与 git commit 的分工：git 记录「改了什么文件」,这里记录「为什么这么改、否定过什么方案」。
>
> 命名规则：一个会话一个文件，`YYYY-MM-DD-简短主题.md`。多个会话同日则加序号。
> 本 README 不需要更新，只管往里加文件。

---

## 记录模板

复制下面这段，填完保存为 `YYYY-MM-DD-主题.md`：

```markdown
# 会话日志 · YYYY-MM-DD · 主题

## 这次要解决什么
（一句话）

## 做了什么
- 
- 

## 为什么这么做（关键决策）
（记录被否掉的方案，避免以后重复讨论）

## 留下的问题
- 

## 相关提交
（commit hash 或「未提交」）
```

---

## 为什么要有这一层

在还没有这一层之前，项目的「本次任务」被写进了 `HANDOFF.md` 并**每次会话覆盖**。
结果是：只有最近一次的记忆，往前翻三轮就什么都没有了，导致重复劳动和方向漂移。

分层之后的规则：

- `PROJECT.md` 稳定层，几乎不动
- `CURRENT.md` 状态层，覆盖式更新
- 本目录 日志层，永久追加

**新会话开始时提供前两份，本目录按需查阅。**
