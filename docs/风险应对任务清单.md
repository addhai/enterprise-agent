### A 组本机验证 runbook（命令 + 预期输出，2026-09-03 实测补充）

> 前置：git bash 进入项目根。**首次跑 pre-commit 需联网**（从 GitHub 克隆 ruff / gitleaks 两个环境），必须先开代理。裸敲 `pre-commit` 会 command not found（Scripts 目录不在 PATH），一律用 `python -m pre_commit`（下划线）。`warning: LF will be replaced by CRLF` 是 Windows 正常现象，不影响。

**0. 确认代理**
```bash
git config --global --get https.proxy
```
- 预期输出：`http://127.0.0.1:7890`（或 Clash 实际端口）；输出为空 = git 未配代理，走系统代理或直连。
- 确保 Clash 正在运行且端口一致，再往下走。

**1. 装 pre-commit 与钩子（一次性）**
```bash
python -m pip install pre-commit
python -m pre_commit install
```
- 预期输出（关键行）：`pre-commit installed at .git/hooks/pre-commit`

**2. 基线验证（干净提交应通过）**
```bash
git add .gitleaks.toml .github/workflows/ci.yml .pre-commit-config.yaml
git commit -m "ci: add gitleaks secret scanning (A1)"
```
- 预期输出（首次多两段 `Initializing environment for https://github.com/...` + 下载，耗时 1~3 分钟）：
```
ruff............(no files to check)Skipped
ruff-format.....(no files to check)Skipped
gitleaks..................................................Passed
[master xxxxxxx] ci: add gitleaks secret scanning (A1)
```
- 分支情况：若 ruff 自动修了 Python 文件会提示 files were modified、commit 中断 → 重新 add 再 commit 一次（本次全是 yaml，预期不触发）。

**3. 反向验证（假密钥必须被拦；文件放根目录，勿放 docs/ 等 allowlist 目录）**
```bash
echo 'AWS_KEY=AKIAQWERTYUIOPASDF12' > secret_test_tmp.txt
git add secret_test_tmp.txt
git commit -m "tmp: negative test"
```
- 预期输出（关键行）：
```
gitleaks..................................................Failed
- hook id: gitleaks
- exit code: 1
... [secret_test_tmp.txt:1] aws-access-key-id ... detected
```
- commit 被拒 = 门禁真生效。

**4. 清理**
```bash
git reset -- secret_test_tmp.txt
rm secret_test_tmp.txt
```
- 预期输出：无报错，`git status` 中不再出现 secret_test_tmp.txt。

**已知故障 1（2026-09-03 实测）**：代理未开时，commit 会在 `Initializing environment` 阶段报
`fatal: unable to access 'https://github.com/astral-sh/ruff-pre-commit/': Failed to connect to github.com port 443 via 127.0.0.1 ... Could not connect to server`
——**这不是 gitleaks 拦截，是网络不通**，开代理后重试即可。代理端口对不上时改 git 代理端口，或让八弟把 `.pre-commit-config.yaml` 换成 GitHub 镜像源。

**已知故障 2（2026-09-03 实测）**：代理开了、两个环境也克隆成功后，gitleaks hook 还要**用 Go 现场编译**，编译下载依赖走 `proxy.golang.org`（Google）——**Go 不读 git 的代理配置**，直连被墙超时：
`go: ... Get "https://proxy.golang.org/...": dial tcp 142.250.71.113:443: connectex: A connection attempt failed ...`
修复（会话内生效；环境编译一次后缓存复用，之后不再需要）：
```bash
export GOPROXY=https://goproxy.cn,direct
git commit -m "ci: add gitleaks secret scanning (A1)"
```
预期输出：`gitleaks...Passed` + `[master xxxxxxx] ci: ...`。备选：`export HTTPS_PROXY=http://127.0.0.1:7890` 让 Go 直接走 Clash。

**已知故障 3（2026-09-03 实测）：gitleaks 8.18 不支持 `[[allowlist]]` 多块写法**
- 症状：`.gitleaks.toml` 把豁免拆成两个 `[[allowlist]]` 块（paths 一块、regexes+commits 一块）后，全历史扫描仍报 9 处泄露（EXIT=1），allowlist 整体不生效。
- 根因：gitleaks 8.18 的配置解析只认单个 `[allowlist]` 表；`[[...]]` 数组表写法在该版本被无视。
- 修复：合并为单一 `[allowlist]`，`paths` / `regexes` / `commits` 三字段共置一块；本机复验两种加载方式均通过——`gitleaks detect --source . --config .gitleaks.toml` 与自动发现（不带 --config，即 CI / pre-commit hook 的实际走法）都 EXIT=0、`no leaks found`（141 commits）。
- 教训：改 gitleaks 配置后必须本机重跑全量 `detect` 复验，不能凭语法正确就提交。

**A1 审计记录（CI 首查 9 findings 定性，2026-09-03）**：

| 类别 | 数量 | 定性 | 处置 |
|------|------|------|------|
| APISIX admin key `edd1c9f0...c8f1` 及变体 | 6 | 官方文档公开默认值（假密钥） | allowlist `regexes` 放行；生产部署必须更换 |
| DashScope key `sk-22ed9fa2...`（仅历史 commit `489edc5e` / `22568515`） | 3 | 真实格式 key，曾入历史 | **拾一去百炼控制台吊销轮转（最高优先）**；现行文件已清理；allowlist `commits` 放行 |

## 技术备注（Technical Notes）

- **CI 配置位置**：`.github/workflows/ci.yml`，密钥扫描挂到现有 `python-security` job（bandit/semgrep 之后）
- **密钥扫描工具选型**：优先 `gitleaks`（单二进制、GitHub Action 成熟）；不引入第二个扫描器以免噪声
- **本机执行前置**：拾一需 Windows + Docker Desktop 常开 daemon；沙箱无法代跑 docker 类步骤
- **红线优先级**：任何涉及真实 key / 付费的操作，先问拾一确认（见风险方案第 6 节）
