## 1. 背景与目标

### 1.1 项目定位

enterprise-agent 是个人简历作品集项目，目标是做出一个**完整、能跑、看得见**的智能客服智能体，对标「阿里云 AI 助理」的形态与能力。它要能放进简历，向面试官证明持证人具备全栈 AI 工程能力：LangGraph 编排、RAG 检索、MCP 工具调用、RBAC 权限、多租户、云原生部署、可观测。

### 1.2 为什么选阿里云 AI 助理作为对标

阿里云在「云上 AI 助理」这个方向上做了多种形态，且都是公开的成熟产品，资料可查、能力可对齐：

- 官网面向开发者的「云上 AI 助理」（aliyun.com/ai-assistant），能力覆盖知识问答、解决方案推荐、产品咨询、资源查询和诊断。
- 控制台内的「计算 AI 助手」「Hologres AI assistant」等，聚焦运维诊断场景。
- 客服工作台 / 智能对话机器人，聚焦人机协同客服场景。

这些形态共享同一套底层能力范式：多轮对话、RAG 知识问答、工具调用执行、工单流转、权限隔离、多渠道接入。我们的项目要复刻的正是这套**范式**，而非某一个具体产品的全部界面。

### 1.3 辩证看待「模仿」的边界

这里必须想清楚一件事：阿里云的能力来自一个商业 SaaS 矩阵，背后是达摩院的超大规模模型、跨产品统一权限（RAM）、以及几百款云产品的数据接入。个人作品集不可能、也不该全盘复制。

更聪明的做法是抓住「可演示、架构完整、能体现工程深度」的子集，用一条清晰叙事串起来：

> 一个能登录、能多轮对话、能查知识库、能执行真实操作（查资源、开工单）、有管理员后台和权限分级的智能客服智能体。

这份文档据此划定 MVP 范围与进阶范围，避免陷入「功能堆砌但无一跑通」的陷阱。

### 1.4 对齐方法（如何「登录阿里云平台对齐功能需求」）

文档中的功能清单已通过阿里云**国际站英文公开文档**完成一轮对齐（来源见第 9 节，均为 alibabacloud.com 或 aliyun.com/en 域名，非中文信源）。后续若要进一步校准，建议按以下步骤操作：

1. 登录阿里云控制台（account.aliyun.com），任意进入一款产品（如 ECS、RDS、Hologres）。
2. 在控制台右侧找到「AI 助手」浮动面板，逐一点开其功能模块卡片，记录交互形态。
3. 打开 aliyun.com/ai-assistant 产品页，对比「知识问答 / 解决方案推荐 / 资源查询 / 诊断」四类能力描述。
4. 进入「智能对话机器人」控制台（若有试用权限），观察知识库配置、对话流、渠道部署的交互。
5. 把观察到的能力回填到第 9 节的对齐清单，标记「已确认 / 待裁剪 / 不纳入」。

## 2. 总体功能架构

系统由五个核心面构成，对外以「浮动聊天组件 + 管理后台」两种形态呈现。

```
┌─────────────────────────────────────────────┐
│                 展示层                        │
│   浮动聊天组件(前端)   管理后台(前端)          │
└───────────┬───────────────────┬─────────────┘
            │ WebSocket / REST  │ REST
┌───────────┴───────────────────┴─────────────┐
│              网关与鉴权层                      │
│   JWT 鉴权 / RBAC 角色校验 / 限流             │
└───────────┬───────────────────┬─────────────┘
            │                    │
┌───────────┴──────┐   ┌────────┴──────────────┐
│  对话编排层       │   │  业务支撑层            │
│  LangGraph Agent │   │  工单 / 用户 / 知识库   │
│  多轮 / 意图路由  │   │  RBAC / 多租户         │
└───────────┬──────┘   └────────┬──────────────┘
            │                    │
┌───────────┴────────────────────┴─────────────┐
│  能力插件层                                    │
│  RAG 检索(chroma)  MCP 工具(资源查询/诊断)      │
│  模型网关(LLM)     监控告警接入                 │
└───────────────────────────────────────────────┘
```

## 3. 功能需求

每条需求编号 FR-xx，标注优先级（P0 必做 / P1 重要 / P2 进阶）与对应阿里云能力来源。

### 3.1 智能对话与多轮问答（FR-01 ~ FR-05）

**FR-01 多轮上下文对话（P0）**  
系统通过 WebSocket `/ws/chat` 提供连续对话能力，Agent 需维护会话上下文，支持追问、指代消解、话题切换。参考阿里云「智能会话」能力：在运维或使用产品过程中提供即时问答、方案或文档指引。  
来源：alibabacloud.com Hologres AI assistant「free-form conversations」。

**FR-02 意图识别与路由（P0）**  
用户输入先经意图分类，路由到「知识问答 / 资源查询 / 故障诊断 / 工单创建 / 闲聊」等处理分支。模仿阿里云对话机器人「多引擎问答（FAQ、任务问答、文档问答）」的分流思路。  
来源：aliyun.com/en 智能对话机器人「多引擎问答」。

**FR-03 答案可溯源（P1）**  
RAG 回答需返回引用来源（文档名、片段、链接），让用户能核对。对应阿里云「文档问答基于上传文档内容作答」的可核查特性。  
来源：alibabacloud.com 智能对话机器人「Document Q\&A」。

**FR-04 建议问题与引导（P1）**  
首轮或空输入时，展示功能模块卡片与建议问题（如「什么是云服务器 ECS」「实例无法登录怎么办」）。对应阿里云 AI 助理「五大功能模块卡片」「提问灵感」。  
来源：aliyun.com/ai-assistant「提问灵感」、Hologres「five feature module cards」。

**FR-05 会话续接（P1）**  
用户重新进入时可恢复历史会话（resume_session 握手）。对应阿里云「对话历史保留 7 天，仅本人可见」。  
来源：alibabacloud.com Hologres「conversation history retained for 7 days」。

### 3.2 知识库管理（FR-06 ~ FR-09）

**FR-06 多形态知识导入（P0）**  
管理后台支持上传文档（PDF/DOC/DOCX/TXT）、导入 FAQ 问答对、爬取指定网站。对应阿里云「文档知识 / FAQ / 网站爬取 / 表格知识」四类。  
来源：aliyun.com/en 智能对话机器人「文档管理、高频问答、网站爬取、表格导入」。

**FR-07 知识索引与检索（P0）**  
上传后自动解析、切片、向量化（chroma 后端），支持语义检索。对应阿里云「系统自动解析文档内容，构建知识索引」。  
来源：alibabacloud.com 智能对话机器人。

**FR-08 知识运营与标注（P2）**  
支持将用户新问法一键加入知识库、聚类标注、相似问题推荐，持续提升覆盖。对应阿里云「在线问答自动化聚类标注、相似问推荐」。  
来源：aliyun.com 客服工作台「在线问答自动化聚类标注」。

**FR-09 知识审核与发布（P1）**  
知识变更需经审核、灰度、发布流程，降低业务风险。对应阿里云「支持知识审核、发布机制，减少业务风险」。  
来源：aliyun.com 智能对话机器人「知识审核、发布机制」。

### 3.3 资源查询与运维诊断（FR-10 ~ FR-13）

**FR-10 资源个性化查询（P1）**  
支持查询「实例、镜像、安全组、云盘、快照」等资源（可先用 Mock 数据或本地样本库模拟）。对应阿里云「资源查询，支持实例、镜像、安全组、云盘、快照等八种资源」。  
来源：aliyun.com 计算 AI 助手「资源查询」。

**FR-11 故障一键诊断（P1）**  
提供诊断入口，用户输入目标资源与时间范围，系统生成诊断报告（CPU/内存/慢查询等维度）。对应阿里云「故障诊断，一键诊断获取详细报告」。  
来源：alibabacloud.com Hologres「CPU/Memory Diagnostics、Slow SQL Analysis」。

**FR-12 操作引导与命令解释（P2）**  
对复杂操作（启停实例、扩容）给出步骤指引；对命令行给出解释。对应阿里云「操作引导、命令解释、划词释义」。  
来源：aliyun.com 计算 AI 助手。

**FR-13 只读安全约束（P0，安全）**  
所有诊断与查询均为只读，不触碰业务数据、不影响实例性能。对应阿里云「AI 操作均为只读，仅针对元数据，不影响业务查询性能」「不连接用户实例、不访问业务数据」。  
来源：alibabacloud.com Hologres FAQ。

### 3.4 故障诊断与工单（FR-14 ~ FR-17）

**FR-14 工单创建（P0）**  
对话中可一键创建工单，记录问题、资源、优先级。对应阿里云客服工作台「自定义工单字段、多级工单自动化流转分派」。  
来源：aliyun.com 客服工作台「工单与 CRM 组合」。

**FR-15 工单跟踪与状态机（P1）**  
工单具备「待处理 / 处理中 / 已解决 / 已关闭」状态流转，用户可查询进度。对应阿里云「工单任务处理、跟踪，自定义流转」。

**FR-16 告警接入自动诊断（P2）**  
接收外部告警事件，自动触发诊断并生成建议。对应阿里云 Service AI Assistant「支持接收告警并 AI 自动诊断」。  
来源：alibabacloud.com DataWorks Service AI Assistant。

**FR-17 解决方案推荐（P1）**  
根据问题上下文推荐解决方案或相似案例。对应阿里云 AI 助理「解决方案推荐」。  
来源：aliyun.com/ai-assistant。

### 3.5 人机协同与转人工（FR-18 ~ FR-19）

**FR-18 转人工（P1）**  
当 Agent 无法解决或用户要求时，转接人工坐席，并携带对话摘要。对应阿里云「无缝转接人工」「呼叫摘要自动生成多标签文本」。  
来源：aliyun.com 客服工作台、alibabacloud.com 智能对话机器人。

**FR-19 会话摘要（P2）**  
对话结束后自动生成带标签的摘要，便于人工接手。对应阿里云 Service AI Assistant「Call summary，动态识别意图，生成多标签摘要」。  
来源：alibabacloud.com DataWorks。

### 3.6 多渠道接入（FR-20 ~ FR-21）

**FR-20 Web 浮动组件（P0）**  
网站内嵌浮动聊天组件，支持展开/全屏。对应阿里云「聊天面板以右侧边栏形式展开，可拖拽宽度或全屏」。  
来源：alibabacloud.com Hologres。

**FR-21 开放 API 与 IM 接入（P2）**  
提供开放 API，支持对接企业 IM（钉钉/飞书/企业微信形态，本作品集可用 Mock 通道验证）。对应阿里云「Web 客户端 + 即时消息客户端（钉钉/飞书/企微）」「开放 API 灵活集成」。  
来源：alibabacloud.com DataWorks Service AI Assistant。

### 3.7 权限、角色与多租户（FR-22 ~ FR-25）

**FR-22 登录与注册（P0）**  
支持账号注册、登录、JWT 鉴权。账号体系含角色分级。

**FR-23 角色分级 RBAC（P0）**  
至少三级：超级管理员（super_admin）、坐席（agent）、访客（viewer）。不同角色可见功能与数据范围不同。对应阿里云 RAM 权限模型「不同场景需不同权限，缺失则功能不可用」。  
来源：alibabacloud.com Hologres「AI Assistant permissions, RAM」。

**FR-24 数据隔离（P0，安全）**  
每个用户仅可见本人会话、本人工单、本人诊断报告。对应阿里云「每个用户仅可见自己生成的内容，不可见他人」。  
来源：alibabacloud.com Hologres。

**FR-25 多租户（P2）**  
支持 workspace 级知识库与配置隔离。对应阿里云 Service AI Assistant「workspace 级知识库（RAG）」。  
来源：alibabacloud.com DataWorks。

### 3.8 管理员后台（FR-26 ~ FR-29）

**FR-26 用户与角色管理（P0）**  
管理员可查看用户列表、分配角色、启停账号。

**FR-27 知识库管理 UI（P0）**  
管理员在后台上传/编辑/删除知识、查看索引状态。

**FR-28 工单管理后台（P1）**  
管理员/坐席处理工单、流转状态、回复用户。

**FR-29 数据看板（P1）**  
提供 KPI 看板（会话量、工单量、解决率、满意度）。对应阿里云「Data Dashboard、多维数据分析、监控大屏」。  
来源：aliyun.com 智能对话机器人「多维数据分析」。

## 4. 非功能需求（NFR）

**NFR-01 性能**  
首字响应（TTFT）在真实 LLM 下不超过 3 秒；常规问答端到端不超过 8 秒；RAG 检索 P95 不超过 500 毫秒。

**NFR-02 可用性**  
单进程 demo 可启动即用；生产部署支持多副本水平扩展（docker compose 已具备雏形）。对应阿里云「弹性扩容、高并发、按量」。

**NFR-03 安全**

- 密码 bcrypt 哈希存储，绝不返回明文或哈希给前端。
- 所有资源/诊断操作只读，不写业务数据。
- JWT 过期与刷新机制。
- 输入做校验与防注入。

**NFR-04 可观测**  
对话链路埋点、工具调用耗时、幻觉计数、错误率。对应阿里云「实时/离线质检、监控大屏」。  
来源：aliyun.com 客服工作台「实时、离线质检」。

**NFR-05 部署**  
支持本地 SQLite 零依赖启动（开发验证用），生产走 Postgres + 向量库，容器化部署。

**NFR-06 兼容性**  
前端兼容现代 Chromium 内核浏览器；后端 Python 3.11+。

## 6. 验收标准（Definition of Done）

**MVP 验收（P0 全绿即算作品集可用）**

1. 用户可用 admin/admin123 登录管理后台，访客可注册。
2. 浮动聊天组件可发起多轮对话，回答基于知识库。
3. 管理后台可上传一份 PDF，问答能引用其内容。
4. 对话中可创建工单，工单在后台可见、状态可流转。
5. 三种角色权限边界正确，越权接口返回 403。
6. 单进程 `uvicorn` 启动 + 前端 `npm run dev` 即可全链路演示。

**进阶验收（P1/P2）**

1. 资源查询/故障诊断工具已接入真实阿里云 OpenAPI（只读，无 AK/SK 时回退样本数据），对话中可查 ECS/RDS/SLB 实例与云监控指标。
2. 转人工携带对话摘要。
3. 数据看板展示实时 KPI。
4. 多租户 workspace 知识隔离。

## 9. 产品形态与架构硬性定位（已决策，2026-08-06 拾一拍板）

以下四点为本项目 MVP 范围红线，开发已按此落地：

1. **形态定位**：对标「客服工作台智能客服」——AI 助手嵌入客服工作台，面向坐席/运维，而非纯 C 端聊天机器人。
2. **数据真实性**：资源查询/诊断**必须走真实云 API**（非样本/mock）。已实现：手写阿里云 RPC Signature V1 签名客户端（`requests` 零额外依赖），只读覆盖 ECS/RDS/SLB 查询 + 云监控指标；`CloudProvider` 抽象层在有 AK/SK 时直连真实云，无密钥时自动回退样本数据（`FallbackProvider`，`source='aliyun+sample'`）。当前测试账号为阿里云试用主账号，暂无实例，故默认开启 `ALIYUN_DEMO_FALLBACK=true`；日后购买资源后改为 `false` 即切纯真实。
3. **多租户 + RBAC**：已纳入 MVP。RBAC 为 `super_admin/admin/agent/viewer` 四级 + 权限点映射 + 依赖注入 + REST 管理 + seed 用户；多租户 `tenant_id` 贯穿全链路（LLM 无法跨租户）。
4. **部署**：必须**容器化多副本（docker）**。已实现：`docker-compose.yml` 应用层（api/ws/worker/rag/frontend）去固定 `container_name`、api/ws 设 `deploy.replicas: 2`，网关 apisix 与数据层（pg/milvus/minio/redis/rabbitmq）保持单实例（有状态）；水平扩展命令 `docker compose up -d --scale api-service=3 --scale ws-service=3 ...`。

> 说明：第 8 节演进建议中"样本数据先跑通"及本节旧版"待确认问题"已随上述决策作废，统一以本节为准。
